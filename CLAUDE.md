# RepoLens AI — Claude Code Context

## Project Purpose

RepoLens AI is an AI-powered GitHub repository intelligence platform. Users paste a public GitHub repository URL and receive a comprehensive technical analysis report generated by an AI pipeline.

**Tagline:** Understand Any GitHub Repository. Instantly.

---

## Architecture

```
Browser (HTML + Tailwind + Vanilla JS)
    ↓
FastAPI (Python 3.12+)
    ↓
GitHub Repository Analyzer
    ↓ ↓ ↓ ↓ ↓ ↓
Repository Scanner → File Analyzer → Dependency Analyzer
Architecture Analyzer → Security Analyzer → Quality Analyzer
    ↓
OpenAI Analysis Agent (gpt-4o)
    ↓
Report Generator
    ↓
Markdown / JSON Output
```

## Coding Conventions

### Python
- Python 3.12+
- Type hints on all function signatures
- Async/await throughout FastAPI routes and services
- Pydantic v2 models for all data shapes
- Descriptive variable names, no abbreviations
- One class/service per file
- Services return typed dicts or Pydantic models

### HTML / Frontend
- Pure HTML5, Tailwind CSS CDN, Vanilla JavaScript
- No React, Vue, or any JS framework
- Each page is a separate HTML file (Jinja2 template)
- Use `fetch()` API for all AJAX calls
- Tailwind dark mode classes: bg-gray-950, bg-gray-900, text-white
- Accent: blue-500 / purple-500
- All API calls go to backend; never expose OpenAI key to browser

### Tailwind Conventions
- Dark workspace: `bg-gray-950` base, `bg-gray-900` cards
- Typography: `text-white` headings, `text-gray-400` body
- Borders: `border border-gray-800`
- Accents: `text-blue-400`, `bg-blue-600`, `hover:bg-blue-500`
- Radius: `rounded-lg` standard, `rounded-xl` cards
- No excessive rounded corners or giant spacing

### API Conventions
- All API endpoints under `/api/`
- JSON request/response bodies
- Standard HTTP status codes
- Auth via HTTP-only session cookie
- Errors return `{"detail": "message"}`

## AI Analysis Rules

- Always construct structured prompts with real repository data
- Never hallucinate bugs or vulnerabilities
- Use hedged language: "potential concern", "may indicate", "appears to"
- Reference specific files when making claims
- Distinguish: `Confirmed observation` vs `Potential concern` vs `Recommendation`
- Severity levels: Critical / High / Medium / Low / Informational

---

## JSON Storage Rules

- Files auto-created in `data/` directory if missing
- Use atomic writes (write to temp, rename) via `utils/storage.py`
- Never load entire JSON files unnecessarily — use ID-based lookups
- Lock-free reads, careful writes to prevent corruption
- Schema: UUID-based IDs, ISO timestamps, structured nested objects

---

## Security Requirements

- Passwords: bcrypt hashing via passlib
- Sessions: HTTP-only cookies, server-side session store (sessions.json)
- Never store plaintext passwords
- Validate all GitHub URLs strictly (must match `github.com/owner/repo`)
- Never execute any code from analyzed repositories
- OpenAI key only server-side, never in responses or HTML
- Input validation on all API endpoints
- Request size limits enforced

## Development Commands

```bash
# Setup
python -m venv .venv
.venv\Scripts\activate       # Windows
pip install -r requirements.txt

# Environment
cp .env.example .env
# Edit .env with your OPENAI_API_KEY

# Run
uvicorn app.main:app --reload --port 8000

# Test
pytest tests/ -v
```
